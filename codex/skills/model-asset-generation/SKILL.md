# Model Asset Generation

将现有 3D 风格包、项目技术配置和本次对象需求组合成可编辑、可验证的模型资产。用户不必懂完整建模术语或编写提示词；默认由 Skill 补齐制作规格并继续执行，不额外拆成“先写提示词”的必经任务。

## 按任务读取

- 定位 Pack、确定位置、组织单个/系列输入及交付记录：读 [inputs-and-outputs.md](references/inputs-and-outputs.md)。
- 执行 Blender 制作、材质、检查或导出：读 [blender-production.md](references/blender-production.md)。
- 对象需要骨架、蒙皮、独立外观通道或形变：再读 [rig-and-controls.md](references/rig-and-controls.md)；静态道具无需此分支。
- 所有正式交付的目标引擎配置和最小验证场景：读 [target-validation.md](references/target-validation.md)。纯草模/仅源文件等用户明确缩小的任务按所选范围记录，不声称完整验收。

本 Skill 可直接读取用户给定的 Pack，不要求先运行建档 Skill。输入包只读，所有新文件进入按输入产物指引解析的本次工作与交付位置，不写回 Skill 目录或源 Pack。

## 执行流程

1. 解析精确 Pack 版本、项目目标及独立 Asset Brief 列表。实际读取必要规则、参考图片和已认可的三维样例；不能仅看到路径或标题就声称使用过参考。
2. 沿用本次输入、项目配置或已有路径约定；缺省时在当前项目内选择不覆盖旧文件的新工作目录，并从中交付独立包。说明路径后继续，只对项目不明、路径冲突或必须覆盖原件等实质问题澄清。
3. 将自然语言补充为可执行规格，保留原话并区分确定要求、合理推断和关键未知。已锁定 Pack 不重复风格访谈；常规细节自行补齐。会改变角色身份、功能、成本或目标兼容性的缺项才澄清。用户只要规格/审阅规格时不自动建模。
4. 默认完成清晰条目的制作、检查和交付后集中复核，单项也不增加必经确认关卡。先检查外形与材质，再进入绑定/形变；仅在用户约定的审美决策点或关键歧义会导致明显返工时暂停。用户要求逐项或分阶段确认时遵守。最终用户批准单独记录。
5. 用 Blender 制作实际模型，按本次用途选择静态/绑定分支。保存编辑源文件、实际脚本、依赖及预览，检查真实产物；修复本次制作引入且能在范围内解决的问题，按制作指引限定恢复次数。需要时运行随附只读检查脚本，但结构报告不替代视觉、变形或引擎测试。
6. 按目标配置导出并建立最小验证场景，实际载入交付资源，检查相机/材质、骨架动作范围和适用的形变中间值及组合。验证代码可调参数或演示测试姿态，不扩展为正式动画或 App 事件逻辑。
7. 交付自包含源文件/纹理、约定格式、控制说明、验证场景及结果。将制作状态、引擎技术验收和用户审美批准分开报告；缺少真实目标运行不能标为验收通过或全部完成。

## 异常与边界

- 无 Pack：先定位用户已有包；仍缺失则说明并提供 `model-style-pack` 入口，不擅自创立新风格。2D Art Pack 不等于 3D 已校准包。
- 草稿 Pack：仅用户明确试做时使用，固定 draft_id 和输入快照并标记 experimental；不自动锁定或逼用户重新走建档流程。
- 必需图片/模型依赖缺失、配置矛盾或风格越界：只暂停受影响项，继续独立清晰条目；批次结束统一列明。不能编造缺失证据。没有进一步授权不自行切换工具服务、上传素材或扩大制作数量。
- 单项返工产生新 attempt，保留旧结果和 supersedes_attempt；不连带重跑成功项。一次批次固定输入版本，不追随 latest 更新。
- 风格级修改需要新版本；只有用户要求改风格时才转交建档流程。模型内容修订或引擎适配不直接改变 Pack。
- 正式动画、运行时状态机、点击/启动等业务逻辑和正式 App 集成不在默认范围。小型姿态/权重测试属于交付验证，不等于正式动作制作。
