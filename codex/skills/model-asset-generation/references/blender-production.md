# Blender 制作与源文件检查

## 预检与执行

探测当前 Blender 可执行文件、版本、Python API 和所需导出器；命令行可运行不证明渲染、rig 或格式链路已验证。优先使用已有 CLI/Python 或已配置工具，不要求额外插件。Blender Python 在 Blender 中运行，不以系统 Python 能否 import bpy 作为可用性条件。

先读取目标 profile；格式与骨架/形变支持是设计约束，不能等全部精修后才发现不支持。复杂角色先用最小网格 + 一根变形骨 + 一个非零形变做导出/载入技术探针；只有涉及这些能力时才需要，不对静态道具强制加 rig。探针是临时测试，不是交付角色或视觉验收。

命令形状（先验证实际路径及本机支持选项）：

```text
<blender> --background --factory-startup --disable-autoexec --offline-mode --python-exit-code 1 --python <build-script> -- <script-arguments>
```

现有 `.blend` 在 Python 脚本参数前加载，并在加载后设置本次输出。CLI 参数依顺序生效，参考 [Blender 命令行文档](https://docs.blender.org/manual/en/5.1/advanced/command_line/arguments.html)，以本机帮助为准。保存命令、脚本与真实版本；脚本异常应导致非零退出码。

不执行不明文件内的自动脚本或下载代码。对用户原模型制作副本，显式指定对象/集合，避免在当前 UI 场景中清空或覆盖。需要任意原驱动才能正确评估时先审阅并记录该限制，不能为省事全局启用自动执行。

若进程在脚本执行前崩溃，先检查启动日志和图形/权限环境，不归因于模型数据。需要在不同权限环境复测时，通过当前环境提供的审批机制运行同一隔离样例；不自行绕过权限或静默更换用户指定的渲染后端。

## 从规格到可编辑模型

1. **外形：** 对齐参考身份、各视角比例与轮廓。粗模用于检查关键比例；用户约定看粗模时再暂停验收，不以默认几何体堆叠冒充风格完成。看侧面/背面避免只为单个视角成立；未知结构记录为设计推断。
2. **表面：** 按风格和目标选择纯色、顶点色、贴图或其组合；没有贴图需求不强制 UV，需要采样图像时验证 UV/坐标路径。保留本次采用的色彩管理，避免混淆贴图颜色、光照和显示变换。
3. **几何整理：** 按用途检查法线、连接、隐藏碎片、轮廓与细节密度。蒙皮弯折区域需要合理变形拓扑；非封闭模型不自动判错，按实际用途检查。单位、轴向、原点和变换须与目标约定一致，不在绑定后盲目 apply transform。
4. **绑定/形变：** 需要时遵循 [rig-and-controls.md](rig-and-controls.md)。保留编辑源，在导出副本中执行格式要求的烘焙/转换，不能通过删除骨架或 shape keys 让导出器“成功”。
5. **预览：** 实际渲染并查看与风格校准可比较的视角、相机和背景。用户既有校准不需重做，但本次不同角色仍要看实际形体。单项和批量均先做必要内部检查，只在用户约定的外形/材质决策点暂停；其余继续到交付再统一复核。

性能预算由项目目标决定。没有约定时报告观察量，只有预算会改变制作方案或本次需要性能验收时才澄清，不臆造“移动端必须多少面”。源网格、求值网格和导出后的三角形数量分开；不能用 Blender 原始多边形数代表实际运行成本。

本次脚本、导出设置或资源路径导致的局部失败，可在同一范围内修复并重跑受影响步骤，无需重新取得制作许可。用户限制优先；未另定时，同一失败默认最多自动修复并复测两次，有新证据才进入下一次，重复同因失败或环境/权限不足则停止该项并报告。成功检查不反复全量重跑；修复不扩成新增主体、付费工具或审美重设计。

## 只读结构检查助手

随附 [inspect_blend.py](../scripts/inspect_blend.py) 在 Blender 内读取当前文件，报告场景、源网格、骨架、shape keys、蒙皮权重统计、材质和图片/链接库依赖；不修改或保存 `.blend`，不执行自动修复。

```text
<blender> --background --factory-startup --disable-autoexec --offline-mode <absolute-model.blend> --python-exit-code 1 --python <skill-dir>/scripts/inspect_blend.py -- --output <new-report.json>
```

报告文件必须是新路径；存在时拒绝覆盖。未载入已保存 `.blend` 时拒绝生成貌似有效的报告。此工具报告整个当前场景的源数据，包括可能不导出的地面/校准对象；按导出集合解释，不机械汇总成预算结论。

重点核查 required control 是否有真实非零变化、蒙皮顶点是否无有效权重、变形骨影响数与权重和、纹理是否丢失。报告中的缺项/异常是定位线索，不自动证明违规：刚性绑定、遮挡分件或特定归一化策略需要结合实际用途。复杂 UDIM、序列、缓存及插件依赖另行检查，工具不会声称覆盖全部依赖。

它不检查渲染质量、穿插、极值姿态、引擎保真或全部导出依赖；禁止因 JSON 生成成功就判通过。渲染检查、形变测试、目标引擎实测仍需真实执行。

## 导出与可移动交付

源 `.blend` 与导出副本分开，明确导出集合和 rest pose。保存导出器版本/设置、资源名/层级和实际输出指纹；不硬编码未经本机验证的导出 API 参数。格式支持以当前官方文档、API 探测及小样实测为依据。

Blender modifier、约束、驱动和程序材质不是天然可移植。将依赖的效果烘焙或在目标实现，分别验证；不能用一张纹理烘死本应由运行时控制的外观。需要形变时避免未经验证的拓扑变更破坏对应关系。

将必要资源打包进源文件或复制成交付包内的相对路径；用户不允许复制的材料保留声明依赖，不以 self-contained 冒充。重开搬迁副本、重新导入最终导出物并执行 [target-validation.md](target-validation.md)，确认检查的确是交付版本而不是旧场景缓存。

正式交付不包含未经请求的正式动作制作、业务事件接线、第三方服务上传或商业插件安装。工具受限时报告缺口，保留检查日志及当前成果，不自行扩大权限。
