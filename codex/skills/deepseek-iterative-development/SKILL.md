# DeepSeek 协作迭代开发

Codex 掌握目标、任务路由、集成和验收；DeepSeek 优先承担边界明确的代码实现。完整交付仍包含所需素材、文案、真实运行验证和版本保留。

## 基础流程与起点

先读取同级 [iterative-development](../iterative-development/SKILL.md)，按其按需读取规则使用协作、验收及运行控制参考。保留其范围、独立验收、预算、停止恢复和达标版本机制，本 skill 只补充 DeepSeek 执行后端和路由。基础 skill 不可用时报告依赖，不假装已具备运行控制。

如果当前已是 DeepSeek 执行进程（任务前缀说明执行角色，或环境标记 `CODEX_DEEPSEEK_WORKER=1`），直接执行收到的任务，不再次调用本 skill 派单。

接续已批准方案、明确决策和现有工作树，不重复设计、不迁回当前聊天目录。其他聊天的记录可作为证据；读取聊天不等于获得向它发消息或启动其中任务的授权。

1. 核对工作树、项目指令、未提交成果、需求来源及验收入口。把聊天中的必要决策落入本轮计划与任务文件，执行进程不能假定看得到原聊天。
2. 运行 `python3 <skill-dir>/scripts/worker.py doctor`，只报告配置、模型目录、CLI 和凭据是否可用。配置缺失时读 [执行与配置](references/runtime.md)。Key 不进入提示词、项目、日志或 skill，由用户在本机录入。
3. 确定本轮范围、时间预算及执行配置。沿用已有确认；缺少时间预算时可准备方案和环境，在启动限时自动迭代前集中询问。修复次数、单任务超时和可调整推理档位写入本轮计划，不把样例数字当成永久限制。
4. 检查执行进程实际具备的文件、命令和工具能力，不假定它继承本聊天的浏览器、MCP、连接器或专业生成能力。

## 按任务路由

读取 [路由与交接](references/routing.md)。按依赖、判断责任和工具能力路由，不按文件后缀机械划分。

| 工作 | 默认执行方 |
| --- | --- |
| 需求取舍、验收标准、接口/数据约束、并行边界 | Codex 协调者 |
| 输入和接口明确、可独立验证的功能实现或定向修复 | DeepSeek 执行进程 |
| 图片、模型、视频等专业生产；指定模型的文案任务 | Codex 调用适用专业 skill 或工具，保留用户已选模型 |
| 需要本聊天独有工具或外部写入授权的操作 | 有对应能力和授权的 Codex 上下文 |
| 跨模块集成、候选冻结、交付状态 | Codex 协调者/明确集成人 |
| 验收、关键回归、实际界面和服务端联调 | 独立 Codex 评审上下文 |

小而高度耦合的修改可由 Codex 直接完成并简记理由，避免派单成本超过实现成本。专业 skill 缺失、运行入口不可用、凭据或权限不足，应补齐条件或记录未覆盖，不能误判为 DeepSeek 编码能力不足。

## 执行、返工与接手

- 用基础 skill 的 `run_control.py` 建立唯一轮次状态。协调者单写控制状态，执行器只写任务回执，不重写轮次状态。
- 用 `worker.py prepare` 生成准确输入版本、允许路径、范围版本和截止约束；`worker.py run` 启动选用 DeepSeek profile 的独立 Codex CLI。例子见运行参考。
- 首次可串行验证闭环；有真实独立任务且预算合适时并行。写任务使用隔离工作树或明确唯一写入者，集成只有一个负责人。执行器阻止两个执行任务同时写同一工作区。
- 执行器监视状态、超时和硬截止，记录事件、用量和路径变更。路径清单是交接约束与事后检查，不是文件级操作系统沙箱；`workspace-write` 实际边界是工作区。
- `completed_unreviewed` 只表示有待审交付，不等同验收通过。查回执、实际 diff、版本和运行证据，再交独立评审。
- 验收失败后把复现、期望、证据及准确候选交回 DeepSeek 定向修复。超过本轮修复上限、重复失败没有新方法或执行后端故障时，由 Codex 自动接手当前任务，记录原因和双方工作量；后续适合的任务仍可委派 DeepSeek。
- `needs_codex_takeover` 是接手信号，不自动调用另一个付费模型。当前 Codex 在原授权和剩余预算内接手，代码仍需独立验收。
- `stopped` / `stale` 不能当接手信号。暂停、停止或到期后不再开发；范围更新先停旧任务，审查成果后明确重派，旧任务不能覆盖新范围。
- 停止/超时须实际结束自有进程组。执行器须保持运行才能监视；它不是后台调度器，不宣称已安排离线续跑。取消父任务时检查执行器和子进程已结束。

## 验收与交付

沿用基础候选与独立验收协议。验收从原始需求和准确候选出发，不继承实现者通过结论。功能、可观察表现、未覆盖与主观待评分开记录；专业素材验证正式应用中的实际效果。

保留最后达标版本。新增协作摘要说明：路由及理由、DeepSeek 请求配置与可核实的生效配置、双方耗时和可得用量、返工及接手原因、候选与验收限制。无法核实的模型/费用标为未知或估算，不用主代理总用量冒充全部费用，不承诺必然省钱或更快。

修改执行器后运行 `python3 <skill-dir>/scripts/test_worker.py` 做离线验证，使用假 CLI 和临时仓库，不调用模型。真实 API 冒烟测试另需范围、预算和凭据，离线通过不能替代。
