# 路由与任务交接

先确定共享数据和接口，再拆实现。适合 DeepSeek 的任务具有明确输入、修改范围、完成条件和验证入口，可以包含合理诊断与测试，不必拆成逐函数机械操作。

Codex 保留尚有产品取舍的工作、跨模块冲突、需要当前上下文工具的操作和证据不足时的判断。代码需要架构决策时先确定约束再交实现，不一概排除服务端或复杂文件。

专业生产沿用项目与用户选择：图片调用既定 Style Pack 的素材 skill，文案按角色口吻和指定生成工具制作。协调者给出尺寸、内容、命名、接口和验收要求，生成者按专业工作流执行，不因有 DeepSeek API 就统一换成纯文本调用。

模型和推理配置确认采用基础 skill 的本轮规则。安装时的 `high` 是可修改起点，不是所有任务都必须使用的档位；重复任务沿用已确认偏好，不用提示词冒充实际设置。

## 契约与回执

任务文件说明原始目标、必要已确认决策、依赖版本、修改范围、共享接口负责人、验收操作与证据、缺口和交付位置。未决产品问题交回协调者，不让实现者自行改变目标。

执行器契约由 prepare 生成：`task_id`、`attempt`、`run_id`、`scope_revision`、`input_version`、`input_fingerprint`、`workspace`、`allowed_paths`、`task_file`、`state_file`、`output_dir`、`timeout_seconds`。协调者将其引用登记到 `current.tasks`，不另建权威轮次状态。

给开发者必要需求和验收标准；给独立验收者原始需求、候选与环境，不提供作者期望结论。开发的测试可复用，但要检查判据。

回执记录 Git HEAD、工作区差异指纹、修改路径和越界路径。指纹不替代冻结候选，集成后仍需保留可复现版本。未提交成果不自动还原、清理或覆盖。事件未回显实际模型/档位时，生效值保持未知；原始 JSONL 和 stderr 留在证据目录，主聊天只读紧凑回执及必要证据。

接手前确认 DeepSeek 进程组退出，检查已有 diff 和证据，保留可用部分，再由 Codex继续。用户停止、截止或范围过期禁止用接手名义继续。模型 API 故障不必停止其他独立专业制作任务。

## 真实校准案例

ring_bear 明信片迭代用于验证工作流，不是固定项目配置：包含 App/服务端、专业插画/邮箱状态图、角色文案和运行验收。已确认语义是：缺卡按当前持有量为零；在途信固定提交时目标合集；款式锁保护当前及未来全部副本。

用案例检验交接能保留决策、安排依赖、沿用专业工具并独立验收。具体工作树、聊天 ID、密钥、截止属于项目计划，不写全局规则。尚未启动项目开发时只做路由演练，不因此修改 App、服务端、素材或文案。
