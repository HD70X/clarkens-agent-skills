# 参考分析与风格校准

## 先分清参考在决定什么

输入不必专业，也不强制逐图填写用途。实际查看图像后，说明采用的解释；用户有明确局部借鉴意向时优先遵守。

| 参考 | 通常提供 | 不应擅自决定 |
| --- | --- | --- |
| 作品截图、场景截图 | 形体简化、视觉密度、材质观感、光影、相机 | 新角色身份、不可见拓扑、原始 shader 参数 |
| 角色设计图 | 身份、轮廓、特征、配色、表情语言 | 已经验证的三维结构和绑定方案 |
| 三视图 | 各方向比例、轮廓、部位对应关系 | 绝对无冲突的几何、截图作品的渲染方式 |
| 用户文字 | 借鉴维度、保留特征、排除项、使用目标 | 未提到的技术预算或隐含批准 |

例如，借鉴游戏中浣熊的形体简化和材质观感来做北极熊，不等于把浣熊的面罩花纹、尾巴或身份复制到熊上。此例仅说明参考角色，不限定所有任务为动物或该游戏。

作品名不够时先寻找并确认代表性截图；不要求用户必须获得原模型。对已有本地图片先查看，不要求再次上传。参考彼此矛盾时，解释具体冲突和影响，问哪个维度优先；不要盲目平均，也不要求用户先懂美术术语。

## 用户可学习的摘要

按当前素材中真正可见的维度解释，不机械填满清单：

- **造型：** 大小体块关系、头身比、轮廓节奏、圆角/棱面、对称与夸张、哪些细节被省略。
- **表面：** 纯色、贴图或顶点色承担哪些信息；粗糙/高光的观感、笔触或颗粒、边缘和法线带来的效果。
- **渲染：** 阴影软硬、明暗层次、环境与接触阴影、背景、构图、相机投影和色彩管理的可见影响。
- **范围：** 允许的主体类别、附属元素、允许变化项和不能改变的风格特征。
- **证据等级：** 分开写“图中能看到”“根据画面推测”“用户明确要求”。仅凭截图不能确定原作是否用了某个节点、贴图通道、真实正交相机或特定拓扑。

给出少量“观察 → 通俗解释 → 制作规则”的对应关系。例如，阴影边缘柔软可以成为观感目标，但不能直接断言某一光源尺寸。复杂白色形体不要为了“白”而抹掉可读的明暗；这是基于当前参考的选择，不是所有风格都用同一灯光。

本次包含校准时，摘要最后说明校准对象和要测试的关键规则；已获制作授权就继续生成可供评价的真实样例，仅在用户约定的确认点或关键风格冲突前暂停。记录制作授权原话，未批准的规则仍为候选。最终可合并展示规则与样例验收，分别保存其批准依据。仅分析时不追加制作或持久化；用户要求保存规则时交付草稿。沉默、脚本成功或助手自检不代表用户批准。

## 用真实三维样例校准

优先采用用户给定目标；未指定时，从本次范围内选择一个能揭示关键规则的代表性主体并说明，只有选择会改变系列范围或关键成本时才澄清。校准是最小可判断的完整样例，不必先交付角色的全部绑定、动画或所有细节。

1. **轮廓/比例阶段：** 用简单材质查看主视角及能暴露歧义的侧面/背面。设计图的关键特征不能被通用几何体堆叠取代。粗模是中间成果，不自动等于最终质量。
2. **表面/渲染阶段：** 在外形稳定后加入所需材质、贴图、光照、相机和色彩管理。记录场景参数，保存 `.blend` 和制作脚本；不能只保留最终 PNG。
3. **反馈阶段：** 每次保留旧尝试，说明本次改了什么；查看真正生成的预览后再向用户展示。用户认可一个样例的多视角检查即可，不强制做第二个主体。

多视角应足以验证该样例的关键立体规则，而非固定生产一整圈高成本渲染。单张截图看不见的结构标为设计补充；不要声称精准还原。

## 帮助解释非专业反馈

“太硬”可能指棱角、阴影、高光或姿态。先依据图像指出最可能的少量解释，例如“你指的是轮廓太方，还是阴影边界太硬？”；不要一次塞入完整术语问卷。无需实际生成新图就能说明时，用现有预览辅助解释。

区分修改对象：

- 单个样例内容：耳朵大小、角色表情、额外道具等，不自动改变跨角色的 Style Spec。
- 全局风格：所有物体都减少小细节、统一高光/阴影语言等，形成新的规则候选。
- 项目渲染适配：同一风格在另一引擎中的实现偏差，优先修正项目适配，不修改已锁定核心。

在达到用户本次反馈目标后停下并展示，不自动扩展成无限调优。若多轮修改仍不清楚，保留比较依据，提出最小的定位问题。
