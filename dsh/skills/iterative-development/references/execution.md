# 持续执行与调度（DeepSeek Harness）

只在用户要求持续执行、定时续跑或后台跟进时读取。先检查当前环境实际提供的能力，沿用已有授权与运行机制；不为了使用 skill 新建一套守护框架。

## 执行方式

- 一个回合可以连续执行多批开发与验收，直到达标、到期、阻断或需要用户决定。当前回合足够完成时直接推进，完成后交付。
- 跨回合的"继续"由 `create_goal` 的自动续轮承担，这是首选机制。每个续轮开头：`get_goal` 核对目标与轮次，`run_control.py check` 核对状态与剩余预算，再决定做什么。不要重复创建 goal，不要用定时任务模拟循环。
- 没有 goal 能力时（例如用户未授权自动续跑），保存状态、成果和下一步，明确告诉用户如何继续，例如再次输入 `/iterative-development 恢复 <run-id>`。skill 文件与控制文件都不是调度器。
- 后台命令用 `bash` 的 `run_in_background`；完成通知会自动到达，不要用 `sleep` 或轮询等待。只有真正被阻塞时才 `job_output(wait: true)`。
- 需要真实墙钟时间（等外部服务、固定时间点复查、长时间挂起）时用 `schedule_create`；日常推进优先靠 goal 回合。

## Goal 生命周期

- 创建：`create_goal(objective, max_goal_rounds)`。objective 写清 run_id、项目、目标、绝对截止、验收门槛和"每轮先 check"；`max_goal_rounds` 按预计批次数加余量设置（如 20–40），不要设成 1 或无穷大。
- 读：`get_goal` 取 goal_id 与 revision；`update_goal` 需要精确 revision。
- 修改目标文本：`update_goal(action="edit")` 要求用户直接请求。范围变化默认写入 run 状态和 scope_revision，不自行改 goal 文本；用户明确要求时再改。
- 暂停/恢复：只有用户明确要求才 `pause` / `resume`。预算到期不是暂停理由，按收尾处理。
- 完成：`complete` 只在目标达成、或到期且已如实交付可用成果后使用；不把"轮次用完"说成达标。
- 阻断：`blocked` 只用于同一具体阻碍连续 3 轮以上仍无法推进，并在 `blocked_reason` 写清具体条件；不确定、缺信息或只是难，都不是 blocked。

每轮结束前更新状态文件；goal 轮次与 run 状态、候选版本必须能对上，不能只活在对话里。

## 定时任务

`schedule_create` 适合"每 30 分钟查一次外部任务""明天上午继续"这类需求，不适合当作开发循环：

- rrule 由一行 DTSTART 加一行 RRULE 组成；用 `TZID=Asia/Shanghai` 保持本地时间，UNTIL 用 UTC。
- 目标是本会话时用 `this_session`；投递会等上一轮结束，停机后只补投最近一次错过的触发。
- 标题用"动作 + 对象"，不写时间、状态或 id；提示词里引用 run_id、控制文件路径和本轮计划，不复制整段历史。
- 创建后记录 schedule_id；`schedule_list` 核对，避免重复创建同一节奏的任务。
- 收尾时用 `schedule_edit` 删除或暂停本轮创建的任务，先核对 id，不误删无关任务。

定时任务依赖机器、应用和会话可用；休眠、断网或关闭后不能保证准点，恢复后先读状态再决定。

## 时间与进程

所有恢复和重试沿用本轮绝对 deadline_utc。close_at_utc 是收尾提醒，不是续期；具体收尾余量可按任务成本配置。临近截止不启动无法完成验证的新批次。

开始修改、测试、合并或派单前运行 `check`。`bash` 单次调用有超时上限：超过上限的命令用后台 job，在步骤之间检查停止或截止，只结束自己启动的进程。`check` 只做只读判断，不会杀进程、取消定时任务或保持机器唤醒；它报告的 may_work / may_start_task 需要调用者遵守。

## 收尾

1. 保存已有成果和停止原因；仍允许工作时先登记候选与评审再 stop，已截止时仅整理已有记录，不补登记新候选。区分自动验收达标、预算结束和阻碍，保留人工待评及未覆盖项、达标版本和最新候选。
2. 停止自有运行器与测试进程：`job_kill` 结束后台 job，`interrupt_agent` 停止仍在运行的子智能体，保留工作区和已有证据。
3. 对仍在运行的已授权协作角色发送一次具体停止要求，用 `list_agents` 核对停止确认；失败如实记录。
4. 取消本轮实际关联的定时任务（`schedule_edit`），不影响无关任务。
5. `update_goal`：达标 `complete`；同一具体阻碍连续 3 轮以上 `blocked`；到期但已交付可用成果也 `complete`，并在报告里写明未达标部分。不创建替代 goal 自动续期。
6. 整理现有报告和剩余项。截止后只允许这类收尾，不再开开发、测试或合并。

暂停来自用户明确要求；恢复暂停轮次保留原截止。已停止轮次若需要继续，由用户决定新一轮目标和预算，使用新 run_id，历史控制与样品保留。
