# 持续执行与调度

只在用户要求持续执行、定时续跑或后台跟进时读取。先检查当前环境实际提供的能力，沿用已有授权与运行机制；不为了使用 skill 新建一套守护框架，也不用 Stop 钩子之类的手段让会话无法停止。

## 执行方式

- Claude Code 的一个回合可以连续执行多批开发与验收，直到达标、到期、阻断或需要用户决定。当前回合足够完成时直接推进，完成后交付。
- 回合结束后不会自动继续。用户要求后续自动继续或定时检查时，按环境能力选择：当前会话内用 `/loop` 自定步调唤醒，或 CronCreate 按固定间隔唤醒，用户要求跨会话保留时才持久化；用户要求每次独立运行时使用桌面应用的定时任务。先查看已有任务，更新匹配任务，避免重复创建。
- 不支持自动续跑时保存状态、成果和下一步，明确告诉用户如何继续，例如再次输入 `/iterative-development 恢复 <run-id>`。skill 文件与控制文件都不是调度器。

保存的提示引用当前 skill、控制文件及项目计划，不复制本轮完整历史到提示中。

提示应说明：每次先检查当前 run_id、状态和绝对截止，复用已确认的推理配置与调整范围；仅处理实质变化、丢失交接和明确失败；正常进度或没有可行动事项时安静；本轮自动验收达标就收尾，只有用户本轮明确要求额外探索时才继续评估扩展；到期或目标全部阻断时如实交付；停止后不自动恢复。通知只在有意义的成果、失败或需要用户决定时出现。

人工最终复核项随候选和证据集中交付；自动验收达标后不因等待主观反馈维持轮询。需要人工决定才能继续实现时，说明受影响范围，继续其他独立目标；没有可推进目标就收尾。

## 时间与进程

所有恢复和重试沿用本轮绝对 deadline_utc。close_at_utc 是收尾提醒，不是续期；具体收尾余量可以按任务成本配置。临近截止不启动无法完成验证的新批次。

开始修改、测试、合并或派单前运行 check。Bash 工具单次调用有超时上限：超过上限的命令用后台运行或项目已有的受控运行器分段执行，在步骤之间检查停止或截止，只结束自己启动的进程。没有运行中检查能力时采用明确超时和分段执行，并说明时间控制的实际限度。后台命令与子智能体完成会自动通知，不要为此轮询。

`run_control.py check` 只做只读判断，不会杀进程、取消定时任务或保持机器唤醒。它报告的 may_work/may_start_task 需要调用者遵守，不能当成系统已强制停止的证据。

本地调度依赖机器、应用和会话可用。会话关闭、机器休眠、断网或任务失败时不能保证续跑；再次运行后先检查原预算和状态，再决定能否继续。

## 收尾

1. 保存已有成果和停止原因；仍允许工作时先登记候选与评审再 stop，已截止时仅整理已有记录，不补登记新候选。区分自动验收达标、预算结束和阻碍，保留人工待评及未覆盖项、达标版本和最新候选。
2. 停止自有运行器与测试进程，用 TaskStop 停止仍在运行的后台命令和子智能体，保留工作区和已有证据。
3. 对仍在运行的已授权协作角色发送一次具体停止要求，核对本轮停止确认；失败如实记录。
4. 取消本轮实际关联的定时唤醒或定时任务，不影响无关任务，不创建替代任务自动续期。
5. 整理现有报告和剩余项。截止后只允许这类收尾，不再开开发、测试或合并。

暂停来自用户明确要求；恢复暂停轮次保留原截止。已停止轮次若需要继续，由用户决定新一轮目标和预算，使用新 run_id，历史控制与样品保留。
